Cornerways/Style guide Rev B · 17 Oct 2026

How every Cornerways site looks and behaves

The rules are short because the shell is built once, in @cornerways/design (v0.17.0), and imported by every app. This page is drawn with the package's own tokens and sizes.

The package README has the component API, and npm run preview shows every component in both themes. Source: cornerways.design/docs/style-guide.md.

Principles

One product, neutral first, big on phones

  • One product. Every app wears the same header, controls and footer from the shared shell. Don't copy shell code into an app; bump the package tag instead.
  • Neutral first. Canvas and surfaces are warm neutrals. Colour is kept for meaning: one brand colour for actions, and each app's accent for its icon and data.
  • Big and simple on phones. Controls are 40px tall with room between them. When a layout doesn't shrink well, build a separate phone layout (Calendar's month view) rather than squeeze the desktop one. Split long pages rather than densify them.
  • Change the look, not the behaviour. Style work doesn't change what a page does. Note bugs you find; fix them separately.
Layout

A full-bleed header and two layout modes

The header is always full width: mark and wordmark on the left (linking to the hub), then / and the app name, which opens the app switcher. Page actions and the account menu are on the right. Pages line up with the header's gutter: 24px, or 16px below 640px.

Colour

Warm neutrals, one brand colour, an accent per app

Terracotta #B4401E is only for primary actions, "today" and the active tab, with one primary button per page. Each app's accent is only for that app's icon and its data (chart lines, categories), never for chrome. Member colours come from the hub and are the same in every app.

Components

Use the shell's controls before writing your own

<Button> primary, secondary (the default) and ghost; <IconButton> 40×40 with active for a toggle that is on. Tap the icon button.

<Segmented> picks one view (<SegmentedMulti> switches several filters on); <Pill> is a round filter toggle with an optional colour dot. Example names.

Theme

Chosen once, in the account menu

  • Light, Dark or Auto, chosen only in the account menu and stored in the shared cw_theme cookie. No app has its own theme toggle or a stray Log out link.
  • Dark applies under html[data-theme="dark"], set before first paint.
  • Auto follows the system on most apps. Weather, Trains and Home follow the time of day in London instead, since they are what the kitchen tablet shows.
  • The hub is light-only.
Kiosk tablet

A mode, not a breakpoint

?kiosk=1 turns on kiosk mode. The shared header and footer are hidden, and boards use large type, no hover and no scrolling. Installed home-screen apps keep the header. What each tablet shows, and when, is set per tablet on the hub (household platform doc, §06).

Changing the shell

Tag it, install it, deploy the hub first

  1. Change cornerways.design, check it in the preview site, then tag it: git tag vX.Y.Z && git push --tags.
  2. In each app: npm install "@cornerways/design@git+https://github.com/iocornerways/cornerways.design.git#vX.Y.Z", then clear node_modules/.vite before restarting the dev server. Editing the tag in package.json by hand isn't enough.
  3. Deploy the hub first, then the apps.
